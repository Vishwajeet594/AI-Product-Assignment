What the matrix says

OAuth2 is the dominant cross-tenant pattern; API-key/token integrations are fastest for single-tenant agent actions. The tool contract is usually not the risk—the right to obtain and distribute credentials is.

Sales/ads/fintech skew toward admin, review, or paid gates. Developer and productivity platforms offer the clearest self-serve adoption path. Several modern AI/media vendors require outreach because their public product pages do not establish an API.

Prioritization

Tier 1: self-serve + broad documented API → build connector now.

Tier 2: documented but paid/admin/review → build auth/action schema, validate customer entitlement.

Tier 3: partner/no public API → do not promise toolkit; request partner API terms or offer browser-mediated workflow only with consent.

MCP count is conservative: only named official/local-MCP paths are included. Community servers are deliberately not treated as vendor support.

Computed clusters: where to build vs. where to ask

Access by category

Developer/productivity apps are mostly self-serve. Ads, commerce, finance, and AI/media contain the highest concentration of admin, paid, partner, and enterprise gates. Use the matrix filters to inspect the underlying rows.

Blockers, ranked

Paid tier and partner review are the dominant blockers, followed by no documented public API. The matrix exposes each blocker class so outreach can be prioritized separately from engineering work.

Method & scope

Evidence links are official documentation where a public developer source exists; otherwise they are the official product/developer page and the finding is deliberately cautious. “Buildable” means a safe agent toolkit can be designed today, not that every endpoint or tenant is accessible without consent. Status varies by plan, region, app configuration, and vendor policy; re-run before launch.
